# Rule Catalog

The single source of truth for react-power-up rules. The write workflow and the review command both use these rules.

## Rule ids

`REACT-<DOMAIN>-<NNN>`, for example `REACT-EFF-001`.

- Ids are **stable**. A rule is never renumbered, and a retired rule's id is never reused. Mark it *Retired* in the index instead.
- `NNN` is three digits, assigned in order within the domain.

| Domain | Covers | Reference |
|---|---|---|
| `TS` | TypeScript: typing props, children, events, refs, context; strictness | `typescript.md` |
| `HOOK` | Rules of Hooks, dependencies, state updates, custom hooks | `hooks.md` |
| `EFF` | Effects: when not to use one, cleanup, races, derived state | `effects.md` |
| `COMP` | Component design: composition, context, controlled inputs, refs, error boundaries, Suspense | `components.md` |
| `JSX` | JSX: keys, conditional rendering, handlers, accessibility basics | `jsx.md` |
| `ACT` | React 19 Actions: `useActionState`, `useOptimistic`, `useFormStatus`, form actions | `actions.md` |
| `STATE` | Where state lives; Zustand; Redux Toolkit | `state.md` |
| `QUERY` | TanStack Query: keys, caching, mutations, SSR hydration | `tanstack-query.md` |
| `RR` | React Router (library mode): loaders, actions, params, navigation | `react-router.md` |
| `TSR` | TanStack Router: typed routes, search params, loaders, auth | `tanstack-router.md` |
| `NEXT` | Next.js App Router: server/client boundaries, data, caching, Server Actions, route handlers, proxy, env | `nextjs.md`, `nextjs-server.md` |
| `FORM` | React Hook Form and Zod: schemas, resolvers, server re-validation, accessible errors | `forms.md` |
| `SEC` | Security: XSS, URLs and redirects, secrets, server input and authorization, cookies, SSRF | `security.md` |
| `PERF` | Performance: React Compiler, memoization, large lists, code splitting, transitions | `performance.md` |
| `TEST` | Testing: tools, queries, async, network mocking, isolation | `testing.md` |

## Severities

| Severity | Meaning | Write mode | Review verdict |
|---|---|---|---|
| `error` | A bug, data leak or security issue: wrong behaviour now or under realistic input | Never produce it. Deviating requires the user to insist (see SKILL.md) | Any `error` → **Request changes** |
| `warn` | Fragile, legacy or unidiomatic: works today, but breaks easily or costs maintainers | Avoid. Only use it with a stated reason | Contributes to **Approve with suggestions** |
| `info` | Style or opinion, including community conventions without official backing | Follow the project's existing convention instead | Mention briefly; never blocks |

A rule that isn't backed by official documentation can't be stricter than `info`. Official documentation here means:
- react.dev
- the Next.js, React Router, TanStack, Zustand, Redux, React Hook Form, Zod, Testing Library, Vitest and MSW docs
- the eslint-plugin-react-hooks and eslint-plugin-jsx-a11y rule docs
- the TypeScript handbook
- WAI-ARIA (including the APG) / WCAG
- the HTML Living Standard
- OWASP.

## Rule template

Every rule in a `references/*.md` file uses exactly this shape:

````markdown
### REACT-<DOMAIN>-NNN · <Imperative title>  `<severity>`

**Why:** <one or two sentences: the concrete failure this prevents>
**Source:** <official documentation URL>

```tsx
// ❌ <what goes wrong>
<minimal bad example>

// ✅
<minimal good example>
```

**Applies:** <package and version range, e.g. "React ≥ 19"> · **Exceptions:** <when the rule doesn't apply, or "none">
````

**Template conventions:**
- **Examples** are minimal and valid TypeScript/TSX for the stated versions. Use `ts` fences for non-JSX code.
- **Applies** gives the versions where the *recommended* fix exists. Below that range, don't flag the pattern. In write mode, use the best alternative the version allows.
- **Exceptions** list the legitimate uses, so reviews don't produce false positives.
- **Project-type scoping:** a rule that applies only to one project type says so in **Applies**, for example "Next.js ≥ 15, App Router".
